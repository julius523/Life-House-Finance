Replit Implementation Guide

Project: Accounting + Expense Management + GAAP-Ready Financial Operations Platform

1. Objective

Build an internal accounting and expense management system that:

* supports controlled double-entry accounting
* connects expenses, approvals, vendors, receipts, and bank statement imports
* produces financial statements
* supports period close
* enforces internal controls
* creates a path to GAAP-compliant operations
* eventually supports financial modeling, budgeting, and forecasting

This is not just an accounting page.
This is a financial operating system inside the app.

⸻

2. Current State

The app already has the early accounting core:

* controlled journal entry posting
* draft → approve → post workflow
* reversal support
* journal entry numbering
* accounting periods
* period close
* posting permissions / separation of duties
* audit trail foundation

This means the project already has the ledger engine.

What is not finished yet:

* chart of accounts
* financial statement reporting
* expense management workflow tied into the ledger
* vendor bill workflow
* account balances and rollups
* bank imports and reconciliations
* accrual workflows
* budgeting / forecasting / modeling
* GAAP reporting layer

⸻

3. Final Product Vision

The final system should let an admin or finance user do all of this in one place:

1. Configure the company’s accounting structure
2. Create and manage a chart of accounts
3. Import expenses from bank statements or receipts
4. Review, categorize, and approve expenses
5. Turn approved expenses into journal entries
6. Manage vendors and bills
7. Reconcile bank activity
8. Close accounting periods
9. Generate:
    * income statement
    * balance sheet
    * cash flow statement
    * trial balance
    * general ledger
10. Build budgets and financial forecasts
11. Run scenario models
12. Maintain full audit logs and permission-based controls

5. Tech Direction

Replit should keep using the existing stack unless something is already locked differently.

Recommended stack assumptions

* Frontend: React / Next.js or current app frontend
* Backend: Node / TypeScript
* Database: Postgres
* ORM: Drizzle
* Auth: existing auth system
* File storage: object storage / Supabase Storage / S3-compatible layer
* Background jobs: queue or cron-style workers if available
* AI parsing: OpenAI or chosen model integration
* OCR / file parsing: PDF and CSV ingestion pipeline

Non-negotiables

* use transactions for every posting workflow
* use database constraints, not just UI validation
* keep accounting logic on the server side
* all financial events must be audit logged
* avoid hard deletes for accounting records

6. Core Business Rules

These rules must be enforced server-side.

Ledger rules

* every posted journal entry must balance
* total debits must equal total credits
* journal entries cannot post into a closed period
* posted entries cannot be edited directly
* corrections must be done through reversing entries and reposting
* each posted entry must have:
    * source
    * created by
    * approved by
    * posted by
    * timestamps
    * period association

Internal controls

* same user cannot perform all stages if separation is enabled
* permissions must support:
    * draft only
    * approve only
    * post only
    * reverse only
    * close periods only
* edits to posted transactions must be blocked
* period close must lock posting

Expense rules

* expense records begin in draft/review state
* only approved expenses can generate accounting entries
* every expense must map to:
    * vendor
    * amount
    * date
    * payment account
    * expense account
    * tax treatment if applicable
* imported expenses should not auto-post without review unless explicitly allowed by settings

Reporting rules

* statements must derive from posted journal entries only
* draft or unposted entries must never affect official reports
* reporting must respect accounting period boundaries

9. Core Workflows Replit Must Implement

⸻

Workflow A: Manual Journal Entry

1. User creates JE draft
2. Adds lines
3. System validates balance
4. Approver approves
5. Poster posts
6. System:
    * assigns JE number
    * finds open period
    * writes posted_at / posted_by
    * locks JE from editing
    * writes audit logs
    * updates balances or balance cache

⸻

Workflow B: Expense Review to Ledger

1. User imports or creates expense
2. Expense enters draft or needs_review
3. Reviewer categorizes:
    * vendor
    * expense account
    * payment account
    * department/class if needed
4. Approver approves
5. On post:
    * create JE
    * debit expense account
    * credit cash / card / payable account
    * link JE to expense
6. Expense status becomes posted

⸻

Workflow C: Vendor Bill

1. Create bill
2. Approve bill
3. Post bill
4. System creates JE:
    * debit expense
    * credit AP
5. Payment later creates second JE:
    * debit AP
    * credit cash

⸻

Workflow D: Bank Statement Import

1. Upload CSV or PDF
2. Parse transactions
3. Normalize and dedupe
4. Show review table
5. AI suggests:
    * vendor
    * category
    * account
6. User confirms/corrects
7. Convert to expense drafts
8. Approved expenses can post to ledger

⸻

Workflow E: Reversal

1. User selects posted JE
2. Click reverse
3. System generates opposite entry
4. Reversal links to original JE
5. Original status updates accordingly

⸻

Workflow F: Period Close

1. Finance admin runs close checklist
2. System confirms:
    * no unposted required entries
    * no unresolved review queues if policy requires
3. User closes period
4. System locks it
5. Posting endpoint blocks all future entries into that period

⸻

Workflow G: Financial Reporting

1. User chooses report type and date/period
2. System aggregates posted lines
3. Applies account type logic
4. Renders statement
5. Supports export

10. Accounting Logic Replit Must Respect

⸻

Double-entry logic

Every accounting event must create balanced debits and credits.

Examples:

Expense paid immediately

* Debit Office Supplies Expense
* Credit Bank / Card

Bill entered but not paid

* Debit Expense
* Credit Accounts Payable

Bill payment

* Debit Accounts Payable
* Credit Cash

Refund

* Debit Cash
* Credit Expense reduction or appropriate account

Reversal

* opposite of original lines

⸻

Normal balance rules

* Assets: debit normal
* Expenses: debit normal
* Liabilities: credit normal
* Equity: credit normal
* Revenue: credit normal

These rules matter for reports and UI balance display.

⸻

Accrual readiness

The first release does not need full advanced accrual automation, but schema and design must leave room for:

* prepaid expenses
* deferred revenue
* accrued liabilities
* fixed asset depreciation
