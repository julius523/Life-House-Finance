Goal

When an expense becomes approved / ready-to-post, the system should generate an accounting draft, not hit the ledger directly. That draft then goes through the existing manual JE workflow: draft → submit → approve → reject → post.

That keeps one control path instead of two Franken-systems duct-taped together.

Task 2 — Expense → accounting draft generation

This is the actual bridge.

Trigger

Default: on expense approval

That is the right default unless you want true cash-basis operational posting behavior. Your earlier direction leans accrual/control-first, so approval is the clean move.

Build

When expense status becomes approved:

resolve category mapping
build JE draft lines
create a manual journal entry draft
attach traceability metadata back to the expense
do not auto-submit
do not auto-post
Typical line logic

For the first slice, keep it simple and explicit:

Debit mapped expense account
Credit mapped cash / clearing / payable account based on rule

You can support:

cash-style categories first
payable-style categories in a later slice if needed
Required outputs
draft created successfully, with:
source = expense
source expense id
created-by system/user indicator
evidence snapshot / memo carrying expense context
if blocked:
expense marked accounting_blocked
reason visible
Acceptance gate
Approved expense with valid mapping creates exactly one draft JE.
Same expense does not generate duplicate drafts on retries.

Task 5 — Idempotent draft generation

You already learned this lesson the fun way: duplicate financial records are bad for stress levels and blood pressure.

Build

For generation from expense:

deterministic idempotency key such as:
expense-draft-{expenseId}
unique constraint on source link or idempotency key
replay returns existing draft
changed payload with same logical source should return conflict or force explicit regeneration flow
Acceptance gate
repeated approval hooks or retry storms create one draft, not many.

Posting trigger recommendation
My recommendation

Generate draft on expense approval

Why:

best control point
clean audit chain
mirrors normal accounting review flow
keeps ledger impact gated behind the existing approval/post pipeline
easier to reconcile than “wait until payment” for the first slice
Not for this first slice

Generating on payment is more cash-basis-friendly, but it complicates:

partial payments
timing differences
whether approval exists before payment
linkage with bills later

Start on approval. Add payment-aware behavior later where it actually belongs.

Hard acceptance gates

This slice is not done unless all of these are true:

Approved expense with a valid mapping creates exactly one JE draft.
No expense can silently post directly to the ledger.
Duplicate triggers/retries do not create duplicate drafts.
Missing mapping blocks generation with a visible reason.
Archived/inactive/non-postable CoA accounts block generation cleanly.
Expense-generated drafts use the existing JE draft workflow, not a parallel path.
Expense detail and JE detail show two-way traceability.
Audit trail shows who approved the expense, who submitted the JE draft, who approved the draft, and who posted it.
Existing manual JE workflow regressions stay green.
Trial Balance is only affected after the draft is actually posted.
