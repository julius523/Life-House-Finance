Phase 1 — Make integrity visible

    * findings are grouped by category
    * sample IDs deep-link to expense, bill, JE, or draft detail when possible
    * unknown IDs show raw value + copy action

    * empty/all-clear state is clean
    * rerun is manual and read-only

2. Guided integrity repair workflow
    Keep this separate from the UI.
    Done means:
    * findings that are safely repairable get explicit repair actions
    * every repair is transactional, idempotent, and audit-logged
    * no silent auto-fixes
    * unsafe findings stay manual-review only
        The integrity notes already established the pattern for safe repairs: transactional, idempotent, audit-safe, and honest about system provenance.  ￼

Phase 2 — Lock permissions and role boundaries

Your own requirements already define the role model and minimum permissions. Finish enforcing them everywhere, not just in the UI. Roles include System Admin, Finance Admin, Finance Staff, Program Manager Approver, Staff Submitter, Read-Only Auditor, and Executive Read-Only. Submitters should only see and act on their own records; auditors are read-only; finance roles handle posting and close.  ￼

3. Full permission matrix task
    Done means:
    * every page and endpoint has an owner role list
    * frontend visibility matches backend enforcement
    * submitters only see their own expenses/receipts/bills where intended
    * finance/admin-only pages are locked properly
    * report access is explicit, not accidental
4. Authorization regression suite
    Done means:
    * admin / approver / finance staff / submitter / auditor test coverage exists
    * unauthorized reads return safe responses
    * unauthorized writes fail closed
    * attachment, receipt, bill, expense, vendor, and program access are all covered

Phase 3 — Prove the workflows end to end

This is the biggest launch-confidence multiplier after integrity.

5. Accounting workflow smoke suite
    Create one end-to-end suite that covers:
    * expense create → approve → accounting draft → submit → approve → post
    * blocked expense → mapping fix → retry → draft created
    * bill accrual draft path
    * bill payment draft path
    * manual JE workflow
    * blocked queue retry / mark not applicable
    * remediation happy path
    * report drilldown to JE detail
    * export happy path
        The system already has the expected workflow rules for expenses, bills, and manual JE approval; this task proves they still work together.
6. State-machine audit task
    Done means every major object has a written allowed-transition table:
    * expenses
    * bills
    * manual JE drafts
    * posted JEs
    * blocked queue items
    * remediation entries
    * not-applicable flows
        This catches weird impossible states before users do.
