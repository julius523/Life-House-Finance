2) Historical backfill matching is explicit

Backfill matching rules:

* If journal_entry_lines.account begins with a 3–6 digit code followed by -, first try exact code match against chart_of_accounts.code.
* If exact code match exists, link that account_id.
* If no exact code match exists, create a new non-system CoA row using:
    * code = parsed numeric prefix if unique, otherwise LEGACY-<stable_hash>
    * name = remaining text after separator, or full string if no remaining text
* If no parseable code prefix exists:
    * code = LEGACY-<stable_hash>
    * name = full legacy string
* Backfill must be idempotent. Re-running must not create duplicate CoA rows.

3) Archive behavior is explicit

Archive means:

* set is_active=false
* never hard delete
* archived accounts remain visible in historical reports and JE detail
* archived accounts cannot be used for new drafts or new postings
* historical posted lines may still reference archived accounts

4) UI access matrix is explicit

* /accounting/coa list/detail: admin + approver
