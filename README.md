# Life House Reentry — Finance Portal

The bookkeeping system for [Life House Reentry](https://lifehousereentry.com), a nonprofit
providing transitional housing and reentry support. The portal handles staff expenses,
vendor bills, accounts payable, manual journal entries, the chart of accounts, month-end
close, and reporting — all under a controlled GAAP-aware general ledger.

Production: https://lifehouseaccounting.replit.app

## What's in here

This is a [pnpm](https://pnpm.io/) monorepo. Each artifact is independently deployable.

```text
artifacts/
  api-server/        Express + Drizzle (Postgres). Source-of-truth for all data.
  finance-portal/    React + Vite UI for finance staff and approvers.
  mockup-sandbox/    Vite preview server for prototyping UI components.
lib/
  db/                Drizzle schema, migrations, and shared DB types.
  api-spec/          OpenAPI contract; client/server types are codegen'd from this.
  ...                Other shared libraries.
docs/
  runbooks/          Short, in-product operator runbooks rendered inside the UI.
scripts/             Repo-wide utility scripts (integrity sweeps, etc).
```

## Stack

- **Backend**: Node.js (TypeScript), Express, Drizzle ORM, PostgreSQL, bcrypt for
  password auth, OpenAPI for the public contract, Zod for runtime validation.
- **Frontend**: React 18, Vite, TanStack Query (codegen'd hooks), Wouter (routing),
  Radix UI + Tailwind (shadcn/ui style), react-markdown for in-app runbooks.
- **Infra**: Hosted on [Replit](https://replit.com) Deployments. CI runs on GitHub
  Actions with a Postgres service container.

## Architecture highlights

- **Contract-first API**: every endpoint is defined in `lib/api-spec` (OpenAPI). Client
  hooks and server types are generated by `pnpm --filter @workspace/api-spec run codegen`.
  The server validates I/O with Zod schemas derived from the same spec.
- **Controlled GL posting**: journal entries are immutable once posted. Corrections go
  through a "reverse and replace" flow. Posting is idempotent on a per-entry idempotency
  key.
- **Period locks**: closed periods reject new postings server-side; reopens are admin-only
  and audit-logged.
- **Role-based access**: four roles — `admin`, `approver`, `submitter`, `service`. The
  `service` role is reserved for the bearer-token API automation account and is hidden
  from the UI. Cookie auth for users; bearer auth for the service account, both behind a
  fail-closed `requireAuth` middleware.
- **Integrity sweep**: 32 read-only SQL checks (`scripts/integrity/sweep.sql`) exposed as
  a typed service, an admin HTTP endpoint, and a CLI. Used to confirm GL invariants
  hold before month-end close.
- **In-app operator runbooks**: short markdown runbooks (`docs/runbooks/`) bundled into
  the finance-portal at build time and surfaced via a sidebar Help drawer plus
  contextual "Help with this page" links on every major page.

## Running locally

This codebase is designed to run on Replit, which manages the database, environment
variables, and workflows for you. To run locally:

1. **Install pnpm** (v10+) and **Node.js** (v24+).
2. **Install dependencies**: `pnpm install`
3. **Set `DATABASE_URL`** to a Postgres connection string of your own.
4. **Push the schema**: `pnpm --filter @workspace/db push`
5. **Set `NODE_ENV=development`** and (optionally) `SEED_DEV_USERS=true` to seed the
   synthetic dev accounts. Do not set `SEED_DEV_USERS` in any production-like
   environment — the api-server boot guard will halt the process if it sees that flag
   outside `NODE_ENV=development`.
6. **Run the API server**: `pnpm --filter @workspace/api-server run dev`
7. **Run the finance portal**: `pnpm --filter @workspace/finance-portal run dev`

## Tests

- API server: `pnpm --filter @workspace/api-server test` — runs `tsx --test` with
  `--test-concurrency=1` (some suites globally `DISABLE TRIGGER` during cleanup;
  parallel runs flake).
- Finance portal: `pnpm --filter @workspace/finance-portal test` — runs `vitest`.
- Both suites run on every push and pull request via `.github/workflows/ci.yml`
  against an ephemeral Postgres 16 service.

## Type checking

- `pnpm run typecheck:libs` — builds the composite lib packages (`tsc --build`).
- `pnpm run typecheck` — full check across libs + every leaf workspace package.
